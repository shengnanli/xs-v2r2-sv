# E1/E2 动手之前：14 个变体 × 每个源 × 四个窗口的 (srcTypeBit, wen) 对表

`python3 extract_probe.py`（只读 G1 golden，秒级，不需要任何工具 license）。
产物 `pair_tables.txt`。

## 为什么先做这张表

E1 要把「每源一对」放宽成「每源一串对」。**放宽之前必须先知道真实的对表长什么样**，
否则只能按族猜 —— 而本 lane 已经因为"按族外推"栽过两次（见 matrix.md 结尾两条）。

## 读出来的四条事实

1. ★**9 个已签核变体每个源都恰好 1 对**★
   （`0:rf` / `1:fp` / `2:vec` / `3:v0` / `2:vl`）。
   ⇒ E1 的退化情形必须逐字复现它们，否则这 9 个会掉绿。**这是 E1 的验收判据。**

2. **访存变体的 src0..2 要 3 对**：`0:rf,1:fp,2:vec`（Ldu / StaMou / StdMoud /
   VlduVstu / VlduVstuVseglduVsegstu）。

3. **V0/Vl 分工确认**：`numRegSrc==5` 的 5 个变体里，src3 恒是 `3:v0`（`isV0`），
   src4 恒是 `2:vl`（`isVp` & vlWen）。与 Chisel `wakeUpV0/wakeUpVl` 逐字对上
   —— ★src3 的判据是 isV0(bit3) 不是 isVp(bit2)，把三张表并成一张就会串位★。

4. ★**E2 的范围比我原先写的小得多，而且精确可定位**★：
   14 个变体 × 所有源 × WB/IQ 两条总线里，**"当拍窗口与入队延迟窗口对表不同"
   只出现在一处** —— `EntriesStdMoud` 的 **src0 / IQ 总线**：
   当拍 `0:rf`，延迟 `0:rf,1:fp`。
   **WB 侧 14/14 全部两窗口相同。**
   ⇒ E2 不是"到处都可能不同"，是**一个变体一个源一条总线**。
     机制仍要支持（按窗口分份），但排期与靶子可以据此收窄。

## 这张表怎么用

- E1 落地时，生成器按本表逐变体产出对表，**不按族写死**（每份留几对是 firtool
  按该变体 WB 总线上真有的 wen 字段 DCE 出来的，不是族常量）。
- 改完核之后，9 个已签核变体的 FM `passing` 必须**逐个不变**：
  25300 / 25010 / 16619 / 15934 / 16549 / 18369 / 18755 / 25001(AluCsrFenceDiv) /
  12136(VfdivVidiv)。
